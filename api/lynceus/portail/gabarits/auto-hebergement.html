{{ _("Le minimum vital") }}

{{ _("L'image est publiée : une instance d'essai tient vraiment en une commande, sur SQLite, sans rien à cloner ni à construire.") }}

docker run -d -p 8000:8000 \
  -e LYNCEUS_LLM_API_KEY={{ _("votre-clé") }} \
  -e LYNCEUS_DATABASE_URL=sqlite:////donnees/lynceus.sqlite3 \
  -v lynceus:/donnees \
  ghcr.io/nashi-cloud/lynceus-api:latest

{{ _("Il ne reste qu'à indiquer http://localhost:8000 dans les réglages de l'extension. Le volume garde l'annuaire d'une relance à l'autre : sans lui, les analyses déjà payées disparaîtraient avec le conteneur.") }}

{{ _("Vous préférez partir des sources, pour lire ou pour modifier ? C'est la même chose en trois lignes :") }}

git clone {% if depot %}{{ depot }}.git{% else %}<{{ _("dépôt") }}>{% endif %} lynceus && cd lynceus/api
cp .env.example .env        # {{ _("y placer la clé du fournisseur de modèle") }}
docker compose up -d

{{ _("La règle à ne pas oublier") }}

{{ _("Une instance exposée sans clés d'accès permet à n'importe qui de dépenser votre argent : chaque analyse appelle un modèle facturé à l'usage. Le compose de production refuse d'ailleurs de démarrer sans clé publique configurée. Ce n'est pas de la prudence excessive, c'est la première mauvaise surprise qui guette.") }}

{{ _("Portail et instance sont deux choses") }}

{{ _("Ce que vous lisez est un portail : il présente le projet, distribue l'extension et délivre des clés. L'instance, elle, analyse et stocke. Elles sont volontairement séparées, parce que le portail détient la clé privée qui signe les clés d'accès : si l'instance était compromise, personne ne pourrait pour autant émettre de clés en votre nom.") }}

{{ _("Un même portail peut d'ailleurs délivrer des clés valables sur plusieurs instances. C'est la première pierre de ce qui deviendra un réseau d'instances fédérées, plutôt qu'un service central de plus.") }}
